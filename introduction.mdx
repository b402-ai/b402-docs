b402 is open-source infrastructure for **agent payments** and **confidential DeFi**.
Live on Solana, Base, and BNB mainnet. Apache 2.0.

## Install for your agent runtime

```bash
npx -y @b402ai/solana-mcp --install
```

One command writes the b402 entry into Claude Code, Cursor, or Claude Desktop.
Eleven tools register: `shield`, `unshield`, `private_swap`, `private_lend`,
`private_redeem`, `quote_swap`, `status`, `balance`, `holdings`, `watch_incoming`,
`wallet_balance`. Mainnet defaults — no RPC config required.

## What's live

| Layer | Where |
|---|---|
| Solana shielded pool (Phase-9 dual-note) | mainnet |
| Solana Jupiter adapter (private swap) | mainnet |
| Solana Kamino adapter (per-user obligation) | mainnet |
| Solana percolator adapter (perp open / close) | devnet |
| Solana MCP server (`@b402ai/solana-mcp@0.0.28`) | npm + mainnet defaults |
| EVM Facilitator V3 (HTTP-402 / x402) | Base + BNB mainnet |
| EVM smart wallets (ERC-7579 Nexus) | Base + BNB mainnet |
| EVM privacy pool (Railgun fork) | Base mainnet |
| Solana Drift adapter, Adrena, Orca | scaffolded — not shipped |

Same b402 program IDs on Solana devnet and mainnet — verifiable from any RPC.
EVM contract addresses are on each chain tab's reference page.

## Three things b402 does that other stacks don't

1. **Per-protocol PDAs derived from a private spending key** on Solana — the
   downstream protocol (Kamino, percolator, future Drift) sees a PDA owner
   per shielded user, not a wallet. Cross-protocol correlation by the same
   user is impossible from the PDA alone.
2. **HTTP-402-native payments** for agents on EVM — the Facilitator settles
   on chain on behalf of a signed EIP-712 authorization, so the agent never
   touches native gas.
3. **MCP-first agent integration** — eleven tools register in one command,
   defaults work for mainnet. Confidential DeFi without a custom integration.

## Trust posture

Pool, verifiers, adapters, and SDKs are open source under Apache 2.0. The
Solana shielded pool ships with a single-contributor Phase-2 trusted setup
today; a multi-party ceremony and external audit are the next hardening
steps. Risk framing in [Trust assumptions](/solana/concepts/trust-assumptions)
on Solana and [Privacy concepts](/evm/concepts/privacy-incognito) on EVM.
